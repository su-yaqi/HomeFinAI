# transactions 业务流程

## 核心流程
1. 用户进入 `/transactions`。
2. 页面先加载分类、预算和经手人候选列表，再按统一分页规则读取交易列表。
3. 用户可按分类、类型、状态、经手人和日期范围筛选。
4. 用户可新增、编辑、删除交易。
5. 用户在新增或编辑交易时，先填写摘要 `summary`，再按需补充详情备注和明细项列表。
6. 用户在新增交易时，经手人默认选择当前登录用户；编辑时可改选其他用户。
7. 用户可全选当前页交易，并对选中记录批量标记为 `ENTERED`。

## 业务规则
- 交易是当前系统的核心业务记录。
- Dashboard 和预算已使用金额都依赖交易数据。
- 交易列表主识别字段已从旧 `description` 语义切换为 `summary`。
- 详情不以原始 JSON 直接暴露给终端用户，而是通过补充说明和明细项结构展示。
