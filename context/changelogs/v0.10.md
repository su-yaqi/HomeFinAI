# v0.10 变更记录

## 基本信息

- **完成时间**：2026-07-29
- **对应 PRD**：无独立 PRD；来源于开发环境与工程流程分阶段改造 Phase 2
- **版本定位**：S/M/H 开发流程、交付证据与仓库级协作规则

## 实现内容

### repository-rules

- 新增根级 `AGENTS.md`，统一正常解决路径、现有改动保护、外部操作授权和内网正式
  部署边界。
- 写入分支选择、逻辑提交、默认分支可发布、授权后推送、合并后短分支清理和
  tag/Release 版本策略。

### risk-and-done-contract

- 建立 S/M/H 三级风险：S 为低风险微调，M 为普通功能，H 覆盖认证、权限、数据库、
  迁移、依赖、部署与跨模块架构。
- 定义与风险匹配的测试、回滚、迁移和 staging 证据。
- 将“完成”定义为范围收敛、风险匹配验证、context 处理、逻辑提交和可追溯状态。

### context-impact

- 每个改动都必须记录 `context impact` 为 `updated` 或 `none`。
- 只有已实现语义事实改变时才更新对应 context；无影响时记录原因，不再机械要求所有
  改动触碰 context。

### policy-tooling

- 新增 `make change-plan`，根据当前变更报告自动推断的最低风险。
- 新增 `make change-check`，校验风险不得低于自动下限，并检查 context 与测试证据。
- H 级检查必须提供回滚、迁移和 staging 证据；只有无迁移时迁移可说明 N/A，
  回滚与 staging 不接受 N/A。
- 新增脚本回归入口 `make test-change-policy`。
- 新增 PR 模板，统一范围、风险、context、验证、H 级证据与剩余风险记录。

## verification

- Bash 3.2 语法与 macOS 本地执行通过。
- 规则脚本夹具覆盖 S 文档、M 普通代码、M 仓库规则，以及 H 认证、权限、模型、
  迁移、依赖和部署路径；同时覆盖风险降级拒绝、缺少测试/staging 证据拒绝、
  context `updated`/`none` 两条路径和完整 H 声明通过。
- 当前 Phase 2 工作区自动最低等级为 M，与局部工程流程变更一致。
- `CONTEXT_IMPACT=updated`、M 级测试证据的完成检查通过。
- PR 模板和 Markdown 链接完成静态检查。
- 仓库现有 pre-commit 文件级检查全部通过，包括 EOF、尾随空格、mypy 与 ty；本阶段
  没有前端、Python 源码或工作流改动，对应 Biome、Ruff、SDK 生成和 Zizmor 正常跳过。

## 设计决策回写

| 设计点 | 最终决策 |
| --- | --- |
| 自动风险 | 只给最低等级；语义判断只能提高，不得降低 |
| Context | 每次记录 impact，只有事实变化才更新 |
| H 级证据 | 测试、回滚、迁移和 staging 均不可省略 |
| 完成定义 | 范围、测试、context、提交和追溯缺一不可 |
| 推送 | 遵循首个稳定点与结束点，但必须先满足外部操作授权 |
