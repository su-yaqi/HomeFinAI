# v0.3 变更记录

## 基本信息
- **完成时间**：2026-05-29
- **对应 PRD**：`context/prds/v0.3/`
- **版本定位**：列表体验与交易经手人关联增强版本

## 实现内容

### list-pagination
- 分类、预算、交易、账户、API Token 列表统一接入分页。
- 默认每页 10 条，支持切换 `10 / 20 / 50 / 100 / 200`。
- 前后端统一采用 `page` 与 `page_size` 作为主分页参数。
- 共享表格分页器沉淀为前端公共组件，后续列表页默认复用。

### categories
- 分类列表接入统一分页规则。
- 分类新增与编辑弹窗支持可视化颜色选择器。
- 保留十六进制色号输入能力，继续沿用 `#RGB` / `#RRGGBB` 校验。

### transactions
- 交易列表接入统一分页规则。
- 列表新增 `description` 展示列。
- 列表中的 `transaction_type` 与 `entry_status` 改为带颜色语义的标签展示。
- 列表支持“全选当前页”，并继续支持批量标记为 `ENTERED`。
- 筛选条件中的经手人改为按用户选择，不再以纯文本作为主筛选维度。

### transaction-handler-linking
- `transaction` 新增 `handler_user_id`，与 `user.id` 建立关联。
- 交易创建与编辑时，经手人默认使用当前登录用户，也允许改选其他用户。
- 交易读取结果新增 `handler_display_name`，展示规则为优先 `full_name`，为空时回退 `login_name`，再兜底遗留 `handler_name`。
- 新增 `/api/v1/users/handler-options` 供交易筛选器和表单读取经手人候选。
- Agent 交易接口同步返回并写入经手人关联字段。

### auth-resilience
- 当前端持有的 Bearer Token 指向已删除用户时，后端会返回 `404 User not found`。
- 前端已将该场景纳入统一登录失效处理：自动清理 token 并跳转 `/login`，不再要求手动移除本地存储。

## 设计决策回写
| 设计点 | 最终决策 |
|--------|---------|
| 列表分页默认值 | 全站业务列表统一默认 `page=1`、`page_size=10` |
| 每页条数选项 | 统一限制为 `10 / 20 / 50 / 100 / 200` |
| 交易经手人关联 | 以 `handler_user_id` 为主，`handler_name` 作为历史兼容回退 |
| 登录失效兜底 | 401、403 和 `404 User not found` 均视为需要重新登录 |
