# v0.5 变更记录

## 基本信息
- **完成时间**：2026-06-01
- **对应 PRD**：`context/prds/v0.5/`
- **版本定位**：交易摘要与柔性详情升级版本

## 实现内容

### transaction-summary-detail
- 交易模型新增 `summary` 与 `detail` 字段。
- `summary` 作为当前主摘要字段，用于列表主展示、API 主读写和导入导出主交换字段。
- `detail` 使用 `jsonb` 持久化柔性详情，支持补充说明和明细项列表。
- 旧 `description` 保留为兼容字段，并默认与 `summary` 对齐。

### transaction-ui
- `/transactions` 页面将单一描述输入改为“摘要 + 详情备注 + 明细项列表”的结构化编辑方式。
- 交易列表主列改为摘要展示，并附带详情备注或前几条明细项预览。
- 摘要在前端提交时要求必填，详情不再以原始 JSON 直接暴露给终端用户。

### agent-transaction-api
- Agent 交易接口新增 `summary` 与 `detail` 读写契约。
- Agent 继续兼容旧 `description` 作为摘要别名，避免旧调用立即失效。
- `detail.items` 中每条明细当前至少要求非空 `name`。

### excel-template-v2
- 系统数据导入导出模板升级到 `v2`。
- `Transactions` 页签从旧 `description` 列切换为 `summary / detail_note / detail_items`。
- 交易导入会把 `detail_note` 和 `detail_items` 解析成统一的 `detail` 对象，导出则以可读文本形式回写。

## 设计决策回写
| 设计点 | 最终决策 |
|--------|---------|
| 交易双层语义 | 用 `summary` 承载短摘要，用 `detail` JSON 承载柔性详情 |
| 详情结构化程度 | 首版不建独立明细子表，先使用 `jsonb` + 结构化前端编辑 |
| 兼容策略 | 保留 `description` 作为兼容字段，并将其默认映射到 `summary` |
| Excel 交换格式 | 使用 `summary / detail_note / detail_items`，避免管理员直接维护 JSON |
| Agent API 升级策略 | 主字段切到 `summary / detail`，同时继续兼容旧 `description` 请求 |
