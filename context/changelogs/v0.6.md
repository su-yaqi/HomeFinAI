# v0.6 变更记录

## 基本信息
- **完成时间**：2026-06-08
- **对应 PRD**：`context/prds/v0.6/`
- **版本定位**：安全能力与 Agent 录入增强版本

## 实现内容

### mfa-self-service
- 当前用户新增 `MFA setup / enable / reset / disable` 四个自助接口。
- 设置页新增 MFA 卡片，支持展示 `secret`、`otpauth_uri`、输入 6 位验证码完成启用。
- `UserPublic` 已稳定暴露 `has_mfa`，前端可直接用来显示启用状态。
- 管理员现在可以对指定账户执行 `Reset MFA`，强制其旧的验证器绑定失效。

### api-token-hardening
- 系统 API Token 管理新增删除能力，管理员可彻底移除无效 Token。
- 新建 Token 后继续只返回一次明文，但页面会额外提示其仅适用于 `/api/v1/agent/*`。
- Token 创建、禁用、删除三种操作都已接入新的前端管理页交互。

### agent-handler-options
- 新增 `GET /api/v1/agent/handler-options`，供外部 Agent 查询可选经手人列表。
- Agent 创建交易时支持显式传入 `handler_user_id`，并返回 `handler_display_name`。
- Agent 更新交易时若显式传入 `handler_user_id: null`，现已统一回退到当前 Token 所属用户，避免留下过期经手人显示名。

### security-fixes
- MFA 启用接口对非法 `secret` 输入增加了解码失败兜底，避免把用户输入错误放大成 500。
- Agent 经手人解析同时校验目标用户是否仍为激活状态。

## 设计决策回写
| 设计点 | 最终决策 |
|--------|---------|
| MFA 启用链路 | 前端先请求 setup，后端只在 enable 成功后真正写入 `mfa_secret` |
| 管理员 MFA 干预 | 管理员重置 MFA 采用清空 `mfa_secret`，不再返回新 secret 给管理员代持 |
| Agent 经手人候选 | 单独提供 `agent/handler-options`，避免 Agent 复用普通用户后台接口 |
| Agent 取消经手人 | 显式传 `null` 时回退到 Token 所属用户，保持交易经手人语义一致 |
| API Token 生命周期 | 支持创建、禁用、删除；明文 Token 仍只在创建时返回一次 |
